# 원본 WMS 비교 분석 연결

## 동작 순서

1. 프론트가 A/B 좌표와 공통 반경(500 또는 1000m)을 POST `/api/public-data/crime-compare`로 보낸다. 인증 없이 공개 조회 가능. JSON/Origin/크기 검증은 기존 API 미들웨어 사용.
2. 서버가 IF_0087 범례의 1~10등급 색상을 검사한다. 중복 색상·잘못된 등급·사전에 검토한 팔레트와 다른 색상은 실패한다.
3. A/B 각각 전체·강도·성폭력·폭력·절도·살인 원본 PNG 6장을 순차 요청한다. 전체는 유형별 평균이 아니다. 기존 CRIME_TYPES를 서버 shared로 옮겨 프론트와 공유한다.
4. 이미지 크기/시그니처/CRC를 검증하고 RGBA로 디코딩한다. 화면 지도나 투명도를 적용한 타일은 읽지 않는다. PNG에 감마 보정·배경 합성·alpha 가중을 적용하지 않는다.
5. 분석 원 안의 픽셀 중심만 집계한다. alpha=0은 E. alpha≥96이며 가장 가까운 범례 RGB의 Euclidean 거리가 8 이하이고 2순위와 거리 차이가 6보다 크면 등급 M. 낮은 alpha/색상 불일치/애매한 색상은 U. 흰색을 배경으로 임의 간주하지 않는다.
6. 기존 공유 순수 함수로 색상 평균 점수/분포/비율/차이를 계산한다. M=0이면 NO_DATA 및 null. 유형 하나라도 원천 실패하면 전체 요청이 실패하며 다른 유형 점수를 복사하지 않는다.
7. 프론트가 좌표/반경/실제 모드 계약을 검증하고 결과를 표시한다. 조건 변경·화면 이탈 시 취소 및 기존 revision/requestId 검사로 늦은 결과를 버린다.

## 좌표와 분석 조건

- 분석 원천: 고정 HTTPS safemap.go.kr/openapi2/IF_0087_WMS. 사용자 지정 URL/스타일/해상도는 받지 않는다.
- WMS 1.1.1, EPSG:4326, bbox는 서쪽 경도/남쪽 위도/동쪽 경도/북쪽 위도. 실제 원천의 버전·축 해석은 후속 실제 호출에서 확인해야 한다.
- 평균 지구 구면 R=6371008.8m의 Haversine 거리로 반경 마스크를 만든다. EPSG:4326은 좌표 표현이고 이 거리 모델은 WGS84 타원체 측지 거리와 동일하지 않다. 엄밀한 지리적 오차 허용치는 아직 미검증이다.
- bbox는 반경+4m를 포함하는 구면 경계, 500m는 512px, 1000m는 1024px. 한 A/B 비교에서는 같은 크기와 중심 근처의 같은 약 2m 간격을 사용한다. 경위도 그리드 전체가 정확한 등거리/등면적임을 주장하지 않는다.
- `nearest-rgb-a96-d8-gap6-v1`은 시험 분류 규칙이다. 실제 원본 진단에서 가장 흔한 alpha=153, 범례와 1~2 정도의 RGB 차이를 확인해 완전 불투명/정확 일치 규칙을 보완했다. 임계값은 공식 기준이 아니고 12장 연동만으로 통계적 분류 정확도가 검증되지는 않는다. 렌더러의 안티앨리어싱으로 U가 커질 수 있다. 거리 한계를 벗어난 색상/낮은 alpha는 U로 남기고 미표시로 추정하지 않는다. 투명도를 픽셀 가중치로 사용하지 않는다.
- 응답에 source/period/palette/classifier/distanceModel/version/조회 시각/A·B geometry를 남긴다. 표시용 지도 타일은 EPSG:5181이고 분석 원본은 EPSG:4326이므로 보간·렌더링 차이가 날 수 있다.

## 서버 활성화

기본값은 닫혀 있다. `.env`는 커밋하지 않는다. 프론트 VITE 변수로 키나 검증 여부를 전달하지 않는다.

```dotenv
SAFEMAP_KEY=발급받은서버키
SAFEMAP_ANALYSIS_ENABLED=false
SAFEMAP_ANALYSIS_VERIFIED=false
SAFEMAP_ANALYSIS_PALETTE=
SAFEMAP_ANALYSIS_PERIOD=
```

1. 모든 유형 스타일에 대한 색상·등급 방향·동일 범례, 축 순서·반경/해상도·원본 PNG와 기준 기간을 확인한다. 공개 API 문서만으로 개별 유형 의미와 기간을 확정할 수 없다.
2. 공공누리4유형에 대한 사용자의 ‘수치화는 변경에 해당하지 않는다’ 판단과 제공기관의 허용 확인은 구분한다. 현재 제공기관 확인을 완료했다고 기록하지 않았다.
3. 확인된 1→10등급 hex 10개를 쉼표로 연결해 PALETTE에 넣고 확인된 관측 기준 기간을 PERIOD에 넣는다. 페이지 수정일/조회일을 대신 넣지 않는다.
4. 검토가 끝난 운영자가 VERIFIED=true 및 ENABLED=true로 설정하고 API 서버를 재시작한다. 플래그는 자동 검증 인증서가 아닌 운영자 설정이다. 현재 실제 검토가 끝난 것으로 설정하지 않았다.
5. 로컬과 EC2 모두 동일 인터페이스 사용. EC2 환경 설정 변경/재시작/배포는 이번 작업에 포함하지 않았다.

## 비용·오류·상한

- 한 비교 최대 범례 1회 + 이미지 12회. 호출 횟수와 최신성을 명확히 하기 위해 현재 분석 결과 캐시 없음. 표시용 타일 캐시는 기존대로 별도 유지.
- 한 프로세스에서 비교 한 건씩 실행, IP당 분당 6건. 원천 10초/전체 45초 제한, 클라이언트 연결 종료 시 중단. 여러 API 프로세스 운영 시 전역 상한은 별도 필요.
- PNG당 3MiB·최대1024² 및 bitDepth≤8, 범례256KiB. HTTP200 XML/HTML·깨진 PNG·해상도 변경·범례 변경을 성공으로 취급하지 않는다. 원천 URL/키/응답 본문은 오류 응답에 포함하지 않는다.
- 원천 실패는 502 ANALYSIS_FAILED, 설정/검토 미완료는 503 ANALYSIS_NOT_VERIFIED, 키 미설정은 503 SOURCE_NOT_CONFIGURED, 처리 중은 503 ANALYSIS_BUSY. 데이터 없음은 200 안의 NO_DATA/null이고 유효한 0점과 다르다.

## 미분류 5% 이하 목표 후보 비교

사용자의 ‘최소5%’ 요청은 미분류 후보비율 5% 이하 목표로 해석해 진행했다. 외부 재조회 없이 같은24장의 SHA256 확인 원본으로 비교했다. 운영 기본 CLASSIFICATION은 alpha96/거리8/간격6을 유지했다.

## 사용자 라벨 5개 및 유사색 추정 반영

사용자가 RGBA별로 직접 지정: (254,222,124,214)→3, (255,242,156,214)→2, (254,238,150,214)→2, (255,255,174,19)→1, (255,248,167,214)→2. `reviewedColors.js`에서 사용자검토 버전으로 관리한다. alpha까지 정확히 일치하면 기본 임계값보다 우선한다. 원본의10색팔레트가 같을 때만 적용하며 임의의 다른 팔레트에 적용하지 않는다.

후속 사용자 요청으로 미확인 유사색 추정을 추가했다. RGB Euclidean거리≤6, alpha차≤3, 다른 등급 기준색과 거리차>2일 때만 사용자라벨을 확장한다. 같은등급의 여러 기준색은 같은라벨로 묶고 비교한다. 낮은alpha색상이라도 이 국소 이웃에 들어오면 추정 가능하지만 범위를 벗어나면 기존 규칙을 따른다. 코드/응답 버전은 reviewed-inferred-v3으로 변경했다.

`evidence.reviewed`는 직접지정픽셀, `evidence.inferred`는 유사색추정픽셀이다. 미분류사유합=U 계약은 그대로다. 실제정답추가검증 없이 추정을 공식라벨이나 학습정확도로 표현하지 않는다. 정확일치/추정off/전체라벨off를 검토함수에서 비교할 수 있고, 공개API에서 사용자 입력으로 규칙을 바꾸는 기능은 없다.

같은24장캐시에서 직접지정7763픽셀, 추정3781픽셀. 전체TOT 후보중미분류 기존→직접지정만→추정포함: A500 16.09→14.91→14.68%, B500 16.80→16.63→16.41%, A1000 18.63→17.74→17.45%, B1000 19.79→19.17→18.89%. 직접라벨/유사색추정만으로5%목표를 달성했다고 표현하지 않는다. 광범위완화후보는 별도미적용상태를 유지한다.

보고서에 원본/분류이미지, 직접라벨전후, 추정전후, 추정색RGBA별빈도·지정등급표를 추가했다. 키/서버env/운영활성화/배포/커밋/푸시 변경 없음. API26개/lint/build 통과. 별도원천재호출없이원본SHA256을확인하고재집계했다.
